# 每项任务的验证协议

## 运行前

1. 在 Godot 项目根目录确认 `git status --short`，记录已有改动；不得覆盖无关文件。用 `command -v godot` 或已验证的可执行文件定位引擎，不猜路径。
2. 阅读当前任务卡列出的源码、场景、Resource、信号和现有测试，先写预期输入/输出与失败边界。若任务卡路径已变化，以 `rg --files` 定位并更新卡片。
3. 新增或修改自动测试时，用受控随机种子、受控计时/敌人容器，避免升级暂停与真实波次使测试非确定。

## 每次修改后

在项目根目录执行（`<GODOT>` 替换为**已定位**的 Godot 4.7.1 可执行文件）：

```text
<GODOT> --headless --path . --editor --quit
<GODOT> --headless --path . --quit-after 300
<GODOT> --headless --path . --script res://tests/smoke/<当前任务专项测试>.gd
```

随后执行 `tests/smoke/` 中与改动相关的既有测试；改变组合根、伤害、升级池、重开或存档时运行全部快速冒烟测试（排除有意长时运行的 soak，另行执行）。不要因命令退出 0 就忽略 Godot Output 中的新错误、资源丢失、重复信号或泄漏。若版本/平台不能执行某命令，记录原因与替代验证，不能写“通过”。

## 每个功能切片的手动检查

- 开局/菜单：实际点击选择、返回、开始、暂停、结算、重开；键盘移动与旧直接启动入口都可用。
- 战斗：实际观察目标、弹体、命中、伤害反馈、持续效果、死亡清理；密集敌人时 UI 与特效仍可读。
- 升级：控制获得经验，检查三选一前置、满级/满格过滤、重复点击、连续升级、刷新次数和中文卡文案。
- 美术：1280×720 截图检查角色/敌人可识别、透明边缘、帧重心、地面接触点、图标比例与对比度；音效需实际听感检查。
- 局外：胜负各结算一次，退出重启读取，重复加载、存档损坏和旧版本档案回退。

## 记录与状态

每项任务的执行记录必须包含：任务 ID、日期/分支/提交（如有）、改动文件、公共接口、测试命令与退出码、GUI 步骤与所见、失败和修复、遗留问题、共享 Resource 是否保持不变。只有专项 + 必要回归通过、手动要求已执行或明确标记无法完成，任务索引才能由“未开始”改为“完成”；未通过时为“进行中/阻塞”。完整五分钟人工游玩、macOS 稳定性、长期平衡分别记录，不得用 headless 流程代替。
