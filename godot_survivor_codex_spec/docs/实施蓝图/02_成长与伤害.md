# 02｜单件成长、升级池和伤害基座

每个任务都需保护当前升级三选一和所有既有武器。现有 `UpgradeDefinition` 是 enum + Resource，`UpgradeSystem` 当前只检查持有、重复获取和最大层数；`weight` 字段目前未参与抽取。可以小步扩展，不必一开始替换整套升级系统。

## T05 单件装备等级/质变运行时模型

- 输入：T04 装备清单、`data/upgrades/upgrade_definition.gd`、`PlayerActor` 的 `_upgrade_stacks` 与 `apply_upgrade()`；先定 D04 的一把样板武器门槛。
- 操作：为每件装备定义稳定 ID、基础等级上限、可选分支 ID 和分支专属升级配置；局内用 `EquipmentProgress`/等效对象按装备 ID 保存 `base_level`、`branch_id`、各分支升级层数。起始/新获装备初始化为同一规则。不要复用全局 upgrade stack 充当装备等级，也不把状态写进 `.tres`。
- 接口建议：`get_progress(equipment_id)` 返回只读快照；`can_choose_branch(branch_id)`、`choose_branch(branch_id)` 在单局规则层验证一次性互斥。观察 UI 的信号只带快照。
- 测试：两把同类型武器如允许重复时如何标识（首版 D02 不重复）；未持有、满级、重复质变、另一分支质变、重开和共享 Resource 隔离。

## T06 升级候选的分类、前置与上限

- 输入：`UpgradeSystem.request_choices()`/`can_offer()`、`UpgradeDefinition.required_weapon_id`、T05 进度；先定 D05。
- 操作：为升级定义通用、获取、基础、质变、分支专属类别和明确的目标装备/分支 ID；集中执行前置/互斥/上限过滤。先保留现有均匀无放回抽取，避免在同一任务引入权重算法。若可用项不足三张，显示实际数量并允许继续游戏，不能卡在暂停态。
- 接口建议：候选上下文包含局内配置和装备状态；`can_offer(definition, context)` 只读，不修改玩家。应用时**重新**校验当前选项与前置，拒绝过期卡或双击。
- 测试：未持有不出专属卡、未到门槛不出质变、已选分支不出其他分支、满级不出、三张不重复、少于三张或零张时 UI 安全恢复。

## T07 一把现有武器的样板质变

- 输入：T05/T06；选一把已有武器，写清每级数值、门槛和一个能看见的分支效果，先不增加新武器。
- 操作：新增该武器的基础升级 Resource、一个质变 Resource、一个质变专属升级；在对应 `WeaponController` 的运行时修正或小型可复用效果组件接入。UI 显示“基础/质变/专属”的不同标记。此任务只验证模型贯通，不应顺手做所有旧武器的质变。
- 测试：获取 → 基础升级 → 质变 → 专属升级的完整链；选择后其它分支消失；效果在发射/命中中真实生效，晚获取仍正确继承通用 Buff，重开归零。

## T08 防具静态定义与运行时装配接口

- 输入：T04 共用六格、`data/weapons/weapon_definition.gd`、玩家运行时清单。先只建“防具能被持有”这条链，不实现减伤。
- 操作：新增 `ArmorDefinition`/等效 Resource（ID、显示、图标、类别、基础升级/分支引用）；清单支持武器与防具共存，UI 能正确显示类别。防具运行时组件只持有状态和信号，不把武器控制器强套给防具。获取、重复、满格、重开统一走 T04 的接口。
- 测试：五把武器 + 一件防具满格、六把武器时防具不可获取、防具不能被当武器发射、无效 Resource 不导致空引用。具体防御数值留到 T11。

## T09 通用属性 Buff 与射程语义

- 输入：`PlayerActor.get_attack_range()`、`WeaponController.get_effective_target_range()`、`WeaponRuntimeModifier`、现有移动/拾取/吸血/暴击升级。先定 D06。
- 操作：列出通用属性表，明确加法/乘法、上下限、叠加顺序。只补当前缺的全武器索敌射程等通用 Buff；防御的实际扣血实现留给 T10。统一让已持有与晚获取的武器读取相同局内通用修正。不要把弹体 `speed × lifetime` 偷换为索敌范围。
- 测试：角色上限较小/武器上限较小两组边界；加成前后索敌距离与弹体实际可达距离分别断言；晚获取、重开、共享 Resource 不变。

## T10 防御/免疫/反伤伤害结算基座

- 输入：`DamageEvent`、`HealthComponent.apply_damage()`、`ActorBase.apply_damage()`、子弹吸血与接触伤害。先在 D07 写出确定公式和事件顺序。
- 操作：增加独立的运行时结算上下文/结果（原始伤害、实际扣血、是否闪避/免疫、来源标签），在生命扣减前统一计算防御与免疫；反伤只对允许的原始命中触发，并标记反伤来源避免无限递归。保留现有 `damaged`/`died` 信号语义或明确兼容迁移；子弹吸血继续只按实际失血结算。
- 测试：零/负伤害、超额伤害、暴击、闪避、免疫、临界死亡、来源已释放、反伤打死攻击者、反伤再次触发、持续伤害标签；原有 `health_damage`、`projectile_base`、`advanced_upgrade` 回归必须通过。
