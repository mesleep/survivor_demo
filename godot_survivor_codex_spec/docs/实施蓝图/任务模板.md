# 新任务卡模板

当现有任务过大或设计稿新增内容时，复制本模板为同目录新文件（如 `07_剑分支.md`），并在[任务索引](任务索引.md)分配稳定 ID、依赖和初始状态。不要把未设计的功能挤进已有任务的“顺手优化”。

```markdown
## T__ 任务名称

- 目标与边界：本次只交付什么；明确不交付什么。
- 设计来源与规则决策：链接源稿章节及 D__；标注已确认/建议/待确认。
- 前置与当前接口：依赖任务、需读取的脚本/场景/Resource/信号、现有兼容行为。
- 数据与运行时：新增的静态字段、运行时对象、持久化字段；谁拥有唯一状态。
- 操作步骤：先测试什么，再改哪个最小接口，然后接 UI/素材，最后做生命周期清理。
- 自动测试：精确输入、断言、边界/失败情况、既有回归测试名。
- 手动验收：在 1280×720 中如何复现，截图/听感/性能证据。
- 完成条件：解析、启动、专项、回归、GUI、文档更新都满足；不能执行的项如何标注。
- 失败回退：若新入口失效，如何保留原可运行路径；不删除旧资源。
```

状态只在任务索引维护；真实命令与退出码只在[执行记录](执行记录.md)维护。设计值写在[规则决策](规则决策.md)或专门数值表，不散落在多个卡片中维护不同版本。
