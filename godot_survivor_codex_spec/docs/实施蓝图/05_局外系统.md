# 05｜金币、存档、解锁与角色

这一链路可在战斗武器开发期间交错推进，但每次只改一个任务。存档位于 Godot `user://`，不保存 Node、Resource 实例或单局场景路径；用稳定 ID 和版本字段。先定 D10/D11 的数值与解锁规则，不在测试里使用真实玩家档案。

## T26 金币掉落与一次性结算

- 输入：`GameSession._on_enemy_died()`、`spawn_experience_gem()`、`end_run()`、`GameResult`。明确敌人掉金概率与击杀结算公式。
- 操作：新增金币拾取物及拾取信号；敌人死亡可同时掉 XP 与金币，掉落概率由数据配置/局内随机源控制。结算只生成一次本局奖励明细，区分已拾金币与按击杀奖励；在存档完成前先留内存余额。交付 D03 金币图标/地面动画。
- 测试：同一敌人死亡信号重复触发、金币拾取重复触发、胜负各结算一次、结算后重开不重发上一局奖励、零击杀/满场金币清理。

## T27 版本化存档与安全读写

- 输入：T26 金币奖励；明确存档版本、默认初始解锁、损坏时处理策略。
- 操作：新增独立 Profile 数据对象与 `ProfileStore`，只序列化标量/稳定 ID：版本、金币、解锁、永久升级等级、刷新次数等。加载时校验字段/类型/范围并迁移旧版本；先写 `user://` 临时文件，验证成功再替换正式文件，失败保留旧档和本局内存结果。菜单显示加载/保存失败状态。
- 测试：首次无档、正常读写、损坏 JSON、缺字段、未知 ID、旧版本迁移、写入失败、连续两次结算、进程退出再进入。测试用独立临时路径，不动玩家正式档案。

## T28 升级选项刷新次数

- 输入：`UpgradeSystem.request_choices()` 与暂停态 LevelUpPanel；先定首版刷新次数获得方式、每次是否消耗、无候选项如何处理。
- 操作：保存本局剩余刷新次数，打开升级卡时提供刷新按钮；先消耗次数并重新抽取**可用**卡，不能重复应用、不能改变已经选择的升级层数。永久刷新加成在开局从 Profile 复制，不在 UI 直接修改存档。
- 测试：零次按钮禁用、一次刷新减一、连续升级保留余额、空池不死锁、暂停态可点击、重开按初始值恢复；测试随机抽取用固定种子。

## T29 武器/角色解锁与购买

- 输入：T02 目录、T27 档案；确定初始可用 ID、解锁价格与非金币条件。
- 操作：目录只描述全部内容，Profile 保存已解锁 ID；主菜单显示锁定/可买/已解锁，并在同一交易入口检查余额、重复购买与写档结果。开局配置只接收已解锁角色/武器；已有旧直启路径用默认可用内容，不能绕过正式菜单购买逻辑。
- 测试：余额刚好/不足、重复购买、非法 ID、存档失败回滚/提示、退出重进；本局候选池在购买后刷新，新开局才生效，进行中的一局不被修改。

## T30 永久强化与开局快照

- 输入：T09 通用属性汇总、T27 档案；按 D11 制定属性增量、上限、价格、叠加顺序。
- 操作：菜单购买共通移速、基础伤害、每秒恢复、吸血、防御等可确定的项目；每次交易先验证上限与余额，成功后写档。`RunLoadout`/启动上下文复制永久等级生成本局初始修正，运行中不再读取档案。没有决定的重置/退款不先实现。
- 测试：各级价格与上限、跨角色共享、开局数值与存档一致、购买后旧局不变化、新局变化、重开/读档一致、`.tres` 不变。

## T31 远程射手角色

- 输入：`CharacterDefinition`、`PlayerActor.initialize()`、T29 解锁；先补一张角色设计卡：起始属性、起始武器、被动适用武器标签、加成公式与上限。
- 操作：用新的角色 Resource/场景外观复用 PlayerActor 和公共组件；被动走角色定义和运行时属性管线，不为射手复制玩家移动/受伤脚本。交付 B02 概念图、待机/四帧移动与头像。
- 测试：两名角色同武器的被动差异、非远程武器不误加成、切换角色后摄像机/移动/拾取/武器正确、解锁条件和重开隔离、GUI 可辨认。
